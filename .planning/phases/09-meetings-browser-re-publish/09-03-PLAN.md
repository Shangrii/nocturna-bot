<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| action_queue payload → bot Discord write | The bot process is the ONLY holder of the Discord token; a queue payload directs which meeting is republished |
| forum thread state → embed edit | An archived/deleted thread is untrusted state the edit must defend against |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-02 | Tampering (IDOR) | meeting_republish payload targeting an arbitrary forum message | mitigate | _republish reads thread_id/starter_message_id from `db.get_meeting(meeting_id)`, NEVER from the payload (RESEARCH Pattern 3); a stale/tampered payload cannot redirect the edit |
| T-09-05 | Denial of Service | archived-thread edit raising Forbidden (bot lacks MANAGE_THREADS) | accept | Degrades to a clean logged action_queue fail() (same UX as a jinxxy sync failure); permission is verified out-of-band in the Plan 05 human-verify checkpoint |
| T-09-06 | Information Disclosure | backfill .md attachment download failure leaking a stack trace / crashing the bot | mitigate | on_ready backfill is guard-wrapped in try/except (gallery idiom); a failed .md download stores a null transcript and logs the gap (D-12), never crashes |
| T-09-SC | Tampering | package installs | accept | Zero new packages (RESEARCH Package Legitimacy Audit: N/A) |
</threat_model>
