# Phase 9 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — server-rendered Jinja2 templates + Alpine.js, hand-authored `app/static/dashboard.css` (not React/Next/Vite; shadcn gate does not apply to this stack) |
| Preset | not applicable |
| Component library | none — bespoke CSS classes, no component framework |
| Icon library | Unicode glyphs (existing convention: 🎙 already assigned to Meetings nav item in `_sidebar.html`) |
| Font | Inter, `var(--font-sans)` — locked in Phase 3 (`03-UI-SPEC.md`), do not reopen |

This phase adds **zero new design-system surface**. It reuses the locked Phase-3 tokens
(`dashboard.css` `:root`) and the Phase-8 jinxxy page shape (`.mod-hdr`, `.card`, `.stat`,
`.action-proof-status`, Alpine state-machine button) almost verbatim. All values below are
pulled directly from the existing `:root` block in `app/static/dashboard.css` — nothing here
is invented; this section documents what already exists so the executor does not re-derive it.

## Spacing Scale

Declared values (must be multiples of 4) — unchanged from Phase 3, already in `:root`:

| Token | Value | Usage |
|-------|-------|-------|
| `--space-1` | 4px | Icon gaps, badge inline padding |
| `--space-2` | 8px | Compact element spacing (row actions, chip gaps) |
| `--space-3` | 12px | Table cell padding, status rows |
| `--space-4` | 16px | Default element spacing, card gaps |
| `--space-6` | 24px | Section/card padding |
| `--space-8` | 32px | Main content padding, empty-state padding |
| `--space-12` | 48px | Modal-overlay padding reference |
| `--space-16` | 64px | Page-level spacing |

Exceptions: none. The transcript collapse/expand toggle and the summary textarea use only
existing tokens (`--space-3` textarea padding per `.reminder-modal textarea`/`.settings-card
textarea` idiom — no new value needed).

## Typography

Unchanged from Phase 3 — exactly 4 sizes, 2 weights, already in `:root`:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 13px (`--text-xs`) | 600 | 1.2 |
| Body | 15px (`--text-sm`) | 400 | 1.5 |
| Heading | 21px (`--text-lg`) | 600 | 1.2 |
| Display | 32px (`--text-2xl`) | 600 | 1.2 |

Meetings-specific mapping:
- Page title (`.ph .ttl` / `.mod-hdr .t`) → Heading (21px/600).
- Row topic, summary preview text → Body (15px/400).
- Row date/time, attendee count, table headers, status badges ("Transcripción no disponible",
  "Solo texto"), timestamps → Label (13px/600, uppercase where the existing `th`/`.k` pattern
  already uppercases — do not uppercase free-form copy like attendee names or summary text).
- No new Display-size usage needed; the meetings module header icon/title reuses `.mod-hdr`
  exactly as jinxxy/gallery/reviews do.

## Color

Unchanged from Phase 3 — 60/30/10 split already locked in `:root`:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0f1115` (`--color-bg`) | Page background |
| Secondary (30%) | `#161a21` / `#1d222b` (`--color-surface` / `--color-surface-2`) | Cards, table rows, textarea background, sidebar |
| Accent (10%) | `#f472b6` (`--accent-meetings`) | **This phase's reserved accent** |
| Destructive | `#f0435a` (`--color-danger`) | Error/failed states only (see below) — **no delete flow exists in this phase, so danger is never a button color here** |

Accent (`--accent-meetings`, `#f472b6`) reserved for, and **only** for:
1. `.mod-hdr` left border on the Meetings page header (`style="--acc: var(--accent-meetings)"`, matching the jinxxy/gallery pattern).
2. The Meetings `.nav-item.on` left border in the sidebar (already wired in `_sidebar.html`).
3. Optionally a `.stat`-style top border if a summary/count tile is added to the list page (not required by D-08/D-09/D-10, add only if the planner needs a "N meetings" tile).

Accent must **never** appear on the "Save & re-publish" button, links, or any interactive
element outside the three uses above — those stay `--color-primary` (`#4f7cff`) per the
existing `.btn` class, exactly like every other module.

Additional semantic colors already available and reused (no new hex values introduced):
- `--color-warning` (`#ffb020`) — "Transcripción no disponible · Transcript unavailable" badge
  (backfilled rows with no stored transcript, D-09/D-12) and the "no forum post to edit"
  disabled-state note (D-14), styled like the existing `.settings-cache-banner` /
  `action-proof-status[data-state="offline"]` warning idiom (border-left + icon).
- `--color-danger` (`#f0435a`) — re-publish failure state only
  (`action-proof-status[data-state="failed"]`), identical to the jinxxy sync-failed state.
- `--color-success` (`#2dd4a7`) — re-publish succeeded state
  (`action-proof-status[data-state="ok"]`), identical to jinxxy sync-done state.

## Copywriting Contract

Bilingual "Spanish · English" convention (locked project-wide, matches `cogs/meeting.py`
terminology: *tema* = topic, *resumen* = summary, *transcripción* = transcript, *acta* = record):

| Element | Copy |
|---------|------|
| Page title | "Reuniones · Meetings" (already set in `_sidebar.html`, reuse verbatim) |
| Page subtitle (`.mod-hdr .s`) | "Consulta el historial y corrige un resumen · Browse history and correct a summary" |
| Primary CTA (re-publish) | "Guardar y republicar · Save & re-publish" (D-10 — single combined save+enqueue button, mirrors jinxxy's one-click Sync button; label swaps to "Guardando… · Saving…" while busy) |
| Empty state heading (no meetings at all) | "Aún no hay reuniones · No meetings yet" |
| Empty state body | "Las reuniones grabadas con /reunion grabar aparecerán aquí · Meetings recorded with /reunion grabar will appear here" |
| Transcript unavailable (per-row/detail, D-09/D-12) | "Transcripción no disponible · Transcript unavailable" |
| No-forum-post state (D-14 — text-channel fallback, cannot re-publish) | "No se puede republicar — esta reunión no tiene una publicación en el foro · Cannot re-publish — this meeting has no forum post" (summary rendered read-only, no textarea/button shown) |
| Transcript toggle (collapsed by default, D-09) | Collapsed: "Ver transcripción · Show transcript" · Expanded: "Ocultar transcripción · Hide transcript" |
| Transcript download link (D-09) | "Descargar .md completo · Download full .md" |
| Re-publish in-flight status | "Republicando… · Re-publishing…" (elapsed timer identical to jinxxy `elapsed()`) |
| Re-publish success | "Publicación actualizada · Post updated" (silent per D-07 — no store/forum announcement copy, this status is panel-local only) |
| Error state (network) | "Error de red · Network error" (reuse existing `.toast[data-kind="error"]` copy verbatim from jinxxy) |
| Error state (re-publish failed) | "No se pudo republicar. Inténtalo de nuevo · Failed to re-publish. Try again" |
| Attendee count label | "N asistente(s) · N attendee(s)" |
| Destructive confirmation | **N/A — this phase has no delete flow.** Re-publish is not gated by a confirm modal: per D-07 it edits the existing forum post silently, matching the jinxxy one-click pattern (click → spinner → result, no "are you sure?" step). |

## Interaction & Layout Notes (non-visual-token, but binding for planner/executor)

These aren't part of the token contract but resolve ambiguity the roadmap/CONTEXT left to
"UI hint" discretion, so the checker/executor have one shared answer instead of improvising:

1. **List page** (`/meetings`, Manager-gated, mirrors `app/routers/jinxxy.py` shape): a single
   `.card` containing a `<table>` of rows, reverse-chronological (D-08). Columns: Topic,
   Date/time, Attendees (count), Summary preview (1–2 lines, CSS `-webkit-line-clamp: 2` or
   equivalent truncation — no new token, just an overflow rule). Each row is a link
   (`<tr>` wrapping an `<a>` per cell, or a `row-action`-styled "view" affordance) to
   `/meetings/{id}`. Empty state uses the `.empty` class exactly like jinxxy's "no products".
2. **Detail page** (`/meetings/{id}`), not a modal: transcript text and an editable summary
   textarea don't fit the existing `.modal-overlay` sizing (`max-height: calc(100vh - var(--space-16))`
   sized for short forms like reminders/confirm). A dedicated page keeps parity with how jinxxy
   is a page, not a modal, and gives the transcript room to breathe. Layout: `.mod-hdr` (topic +
   date), then a Summary `.card` (textarea + "Guardar y republicar" button + Alpine state
   machine identical to jinxxy's `jinxxySyncApp` shape — disabled/spinner/result), then a
   Transcript `.card` (collapsed by default per D-09, toggle button, download link, or the
   "Transcripción no disponible" warning badge for null-transcript rows).
3. **Attendee display**: reuse the existing `.role-chip-list` / plain chip styling (already
   defined in `dashboard.css` for role chips) for attendee name chips — no new CSS class needed,
   just names instead of role names, no Discord IDs (D-03).
4. **No-forum-post rows** (D-14): the detail page renders the summary as plain read-only text
   (not a textarea) with the warning-styled note in the table above, and does not render the
   Save & re-publish button at all (not merely disabled) — matches D-14's "enabled only for
   rows that have a forum message to edit."
5. **Backfill (D-11–D-13)**: no dedicated UI is specified by CONTEXT.md (trigger mechanics are
   explicitly Claude's Discretion — command vs. guarded startup task). If the planner exposes a
   manual "run backfill" trigger in the panel, it MUST reuse the jinxxy one-click button +
   state-machine pattern verbatim (same button/status classes, same bilingual copy shape:
   "Importar reuniones antiguas · Import legacy meetings") rather than inventing a new pattern —
   but this UI-SPEC does not mandate that a button exists; a one-time startup-guarded import with
   no button is equally valid per D-13's idempotency requirement.
