<objective>
Make the last-sync record and the activity log informative for every trigger: persist the D-09
added/updated/removed counts, name the trigger source and actor in the D-12 activity line, and
add the D-10 exception-type → fixed bilingual category mapper that keeps raw third-party
exception text out of the panel.

Purpose: roadmap success criterion #1 requires a Manager to "see the status/result of the last
sync". Without this plan the last-sync card is a bare tick and a product count, and a failure
would leak `str(exc)` (which can carry API URLs and status codes) to the dashboard.
Output: `sync_error_category()`, a widened `_record_sync_status`, and their tests.
</objective>

  <action>
Add a module-level function (not a method — Plan 05's `action_queue_worker` handler imports it
directly) placed near `_is_staff`:

`def sync_error_category(exc: BaseException) -> str:`

It returns one of exactly three strings, chosen by `isinstance` on the exception TYPE, checked in
this order:
  1. `jinxxy_api.JinxxyAPIError` →
     `"No pude contactar con Jinxxy · Couldn't reach Jinxxy — revisa los logs · check the logs"`
  2. `github_publish.GitHubPublishError` →
     `"No pude publicar en la web · Couldn't commit to the site — revisa los logs · check the logs"`
  3. anything else →
     `"Falló la sincronización · Sync failed — revisa los logs · check the logs"`

These three strings are locked verbatim by the UI-SPEC Copywriting Contract. Define them as
module-level constants (e.g. `_ERR_JINXXY`, `_ERR_GITHUB`, `_ERR_GENERIC`) so the tests and any
future caller reference the same literals.

Hard requirement: the returned string must NEVER interpolate `str(exc)`, `repr(exc)`,
`exc.args`, a status code, a URL, or any other attribute of the exception. `str(exc)` from
`jinxxy_api` and `github_publish` can carry API URLs and HTTP status codes; nothing raw may
reach a panel surface (D-10, and the project's no-secrets invariant). The exception detail
continues to reach the logs only, via the existing `log.exception(...)` calls.

Docstring must state: this is D-10's category table; callers map BEFORE the string reaches
`action_queue.fail(id, str(exc))` or any render layer; the mapping is by exception type, never
by message content.

   Success (`ok=True`):
     - `source == "scheduled"` (or any unrecognised value) →
       `"Sync de Jinxxy programado · Scheduled Jinxxy sync"`

       `f"Sync de Jinxxy desde el panel{suffix_es} · Jinxxy sync from the panel{suffix_en}"`

       `f"Sync de Jinxxy desde Discord{suffix_es} · Jinxxy sync from Discord{suffix_en}"`
   Failure (`ok=False`):
     - `source == "scheduled"` →
       `"Falló el sync de Jinxxy programado · Scheduled Jinxxy sync failed"`
     - `source == "panel"` →
       `f"Falló el sync de Jinxxy desde el panel{suffix_es} · Jinxxy sync from the panel failed{suffix_en}"`

       `f"Falló el sync de Jinxxy desde Discord{suffix_es} · Jinxxy sync from Discord failed{suffix_en}"`

Do not alter the enumerate → map → merge → commit ordering inside `_run_sync` (T-09-15
