Shared helpers in the module:

`def _sync_payload(sync_row, online: bool) -> dict` — assemble the panel's status contract:
```
{
  "bot_online": online,
  "never_synced": sync_row is None or sync_row["last_run_utc"] is None,
  "running": bool(sync_row and sync_row["running"]) and online,
  "started_at": sync_row["started_at"] if sync_row else None,
  "source": sync_row["source"] if sync_row else None,
  "actor_name": sync_row["actor_name"] if sync_row else None,
  "last_run_utc": ..., "ok": ..., "product_count": ...,
  "added": ..., "updated": ..., "removed": ...
}
```
Two rules are load-bearing:
  - `running` is ANDed with `online`. D-06: when `bot_heartbeat` is stale the mirror is void, so a
    bot that is currently down never shows a phantom sync in progress and the button re-enables.
  - `never_synced` must use the `last_run_utc is None` test, not `sync_row is None` alone —
    the bot's boot-time `clear_jinxxy_sync_running()` creates the id=1 row before any sync has
    ever completed (D-15).
Do NOT include the raw `error` column in this payload. The panel renders the D-10 category from
the action result; the raw column is for operators and stays server-side.
Map `ok` to a real bool or None (`bool(row["ok"]) if row["ok"] is not None else None`).

   Jinxxy Store"`, `icon="🛍"`, `accent="var(--accent-jinxxy)"`, `sync` (the `_sync_payload`

2. `@router.get("/jinxxy/status", response_class=JSONResponse) async def jinxxy_status(roles=...)`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → FastAPI route | Untrusted request crosses here; identity comes only from the signed session |
| FastAPI app → shared sqlite | The app writes `action_queue` rows the bot will execute with real credentials |
| sqlite → JSON response | Anything put in the status payload becomes Manager-visible |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Elevation of Privilege | `/jinxxy`, `/jinxxy/status`, `/jinxxy/sync` | mitigate | Every route carries `Depends(require_manager)` — the existing shipped tier dependency, never an ad-hoc check. Enforced by a grep count of exactly 3 and by the parametrised `test_jinxxy_routes_reject_non_manager`. |
| T-08-06 | Tampering | D-04 dedupe bypass via `POST /api/actions` | mitigate | `"jinxxy_sync"` is deliberately NOT added to `app/main.py::_ALLOWED_KINDS`, so the generic unconditional-enqueue endpoint returns 422 for it. `POST /jinxxy/sync` (which calls `enqueue_deduped`) is the only sanctioned path. Enforced by grep. |
| T-08-02 | Information Disclosure | `/jinxxy/status` payload | mitigate | The raw `jinxxy_sync_status.error` column (which can carry upstream URLs and status codes) is excluded from the payload; the panel renders the D-10 category from the action result instead. Asserted by `test_status_does_not_leak_the_raw_error_column`. |
| T-08-22 | Information Disclosure | product catalog exposure | accept | `/jinxxy` and `/jinxxy/status` serve only the seven sync-owned `store_snapshot` fields, all of which are already public on the live storefront, and only to an authenticated Manager. No credentials, tokens or internal ids beyond `checkout_url` are exposed. |
| T-08-05 | Denial of Service | repeated Sync clicks | mitigate | `enqueue_deduped` returns the existing pending/claimed action id, so N clicks cost at most one Jinxxy enumeration + GitHub commit (D-04), with the bot-side lock as the second layer (D-01). |
| T-08-23 | Spoofing | `payload["actor_name"]` | mitigate | Derived only from `roles["username"]` (OAuth-verified session, Plan 02) with a `discord_id` fallback. The route accepts no request body at all, so no client-supplied name can enter the payload. |
| T-08-24 | Elevation of Privilege | app holding bot credentials | mitigate | The route only inserts a queue row; it never imports `core.jinxxy_api` or `core.github_publish` and never performs a sync. The locked project invariant (the app holds no Jinxxy/GitHub/Discord credentials) is preserved. |
| T-08-SC | Tampering | package installs | accept | This plan installs zero packages. |
</threat_model>
