Add `async def _handle_jinxxy_sync(self, payload: dict) -> dict:` after the gallery/review
handlers:

  1. `jinxxy_cog = self.bot.get_cog("Jinxxy")`. If `None`, raise
     `RuntimeError("JinxxyCog no está cargado · JinxxyCog is not loaded")` — same bilingual
     "no está cargado" idiom the gallery/review handlers use. Add an inline comment recording
     that the lookup key is `"Jinxxy"` (the `name=` kwarg on the `GroupCog` declaration), not the
     class name, so a future refactor does not silently break the lookup.
  2. `actor_name = payload.get("actor_name") or None`. The payload carries NO `source` field:
     the trigger source is inferred as `"panel"` by construction, because `/tienda sync` and the
     scheduled `_poll` never touch `action_queue`. `actor_name` is in the payload because
     `_run_once` hands the handler only the payload — there is no other channel from the app to
     this handler for the D-07/D-12 display name.
  3. In a `try`, call `result = await jinxxy_cog._run_sync_guarded(source="panel", actor_name=actor_name)`.
     Never call `_run_sync` or `_announce` directly, and never reimplement any sync step —
     `_run_sync_guarded` owns the overlap guard, the mirror, and the single announce (D-11).
  4. `except Exception as exc:` → `log.exception("action_queue: jinxxy_sync falló")` then
     `raise RuntimeError(sync_error_category(exc)) from exc`. Mapping here (rather than in the
     shared `_run_once`) keeps the generic dispatcher untouched, and it guarantees that the
     string reaching `action_queue.fail(id, str(exc))` — and therefore the panel — is one of the
     three fixed bilingual categories, never raw third-party text (D-10).
  5. On success, return a SHAPED dict, never the raw reconcile result:
       - if `result.get("already")` → `return {"already": True}` (D-01: a collision is a benign
         success; the panel renders "Ya se está sincronizando · Sync already running").
       - otherwise `return {"already": False, "changed": bool(result.get("changed")),
         "added": len(result.get("added") or []), "updated": len(result.get("updated") or []),
         "removed": len(result.get("removed") or []),
         "products": len(result.get("products") or [])}`.
     Shaping is mandatory, not cosmetic: the raw reconcile result contains a full list of product
     dicts, which `action_queue.complete` would JSON-serialise into the `result_json` column and
     ship to the browser on every status poll. The panel needs only the counts (D-09).

Do NOT modify `_run_once`, `_tick`, the retry/backoff behaviour, or any existing handler.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
