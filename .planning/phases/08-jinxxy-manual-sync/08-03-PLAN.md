Add a new method `async def _run_sync_guarded(self, *, source: str, actor_name: str | None = None) -> dict`
placed immediately after `_run_sync`. Behaviour, in order:
  1. Fast path (D-01/D-03): `if self._sync_lock.locked():` — log at INFO level naming the
     skipped source (e.g. "jinxxy: sync ya en curso, omito el disparo (%s)", source) and
     `return {"already": True}` IMMEDIATELY. Do NOT await the lock. Blocking here would park
     `ActionQueueCog`'s single one-action-per-tick dispatch slot for the whole multi-minute sync
     and stall every other queued action behind it (D-01's mechanical reason). This same early
     return is D-03's poll skip-and-log: no sync, no announce, no error.
  2. `async with self._sync_lock:` — inside, first
     `await asyncio.to_thread(db.mark_jinxxy_sync_running, source, actor_name)`, then
     `try: result = await self._run_sync()` / `finally: await asyncio.to_thread(db.clear_jinxxy_sync_running)`.
     The mirror is written and cleared around exactly the span the lock covers so the two can
     never disagree while the bot is up (D-02's binding requirement). The `finally` must run on
     the exception path too, then let the exception propagate unchanged.
     Wrap ONLY the mirror writes (not `_run_sync`) in their own try/except that logs and swallows
     a mirror-write failure — a mirror write must never change the sync outcome, matching
     `_record_sync_status`'s existing discipline.
  3. After the `async with` block exits (lock released): `await self._announce(result)`. This is
     the ONE AND ONLY `_announce` call site in the file after Task 2. Announcing outside the lock
     releases the guard as early as possible; announce-send failures stay cosmetic (WR-09,
     already logged and swallowed inside `_announce`) and must not fail the caller.
     Because `_run_sync` re-raises on failure, control never reaches this line on a failed sync —
     D-05's "nothing is announced on failure" is preserved by construction.
  4. `return result`.

Docstring must state: this is the single guarded entry point for EVERY sync trigger (the
scheduled `_poll`, `/tienda sync`, and the `action_queue` handler); callers must never call
`_run_sync` or `_announce` directly; a `{"already": True}` return is a benign success (D-01),
not an error, and carries none of the `added`/`updated`/`removed`/`changed`/`products` keys, so
callers must use `.get(...)`.

`_run_sync`, `_announce`, `_build_announce_embed`, `_record_sync_status`, `_on_poll_error` and
the poll cadence are all UNCHANGED in this task.
